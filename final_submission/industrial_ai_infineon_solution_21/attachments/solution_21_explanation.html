Solution 21: Template-Boosted Evidence Bridge

This solution answers the final modeling question: can we combine a real trained model, like XGBoost, with the __FAMILY__ template idea that made our OOD strategy stronger? The answer is yes, and the diagnostic below shows why template normalization is the important part.

The submit-ready CSVs still come from the strongest evidence cascade from Solution 20: exact full-route memory, valid-partial lattice, paired-length completion guard, and template fallback. The XGBoost bridge is included as trained-model evidence and as a future path for a final hybrid model.

Detailed Explanation

What changed from Solution 20?

The official prediction path is intentionally conservative. It uses the same cascade as Solution 20 and writes the same three required submission files: nextstep.csv, completion.csv, and anomaly.csv. On the released participant inputs it predicts 600 valid rows and 987 anomaly rows. The diagnostic coverage is still: full-route exact prefix coverage 1.0000, valid-lattice coverage 0.5000, and paired-length fallback coverage 0.0000.

The new part is the trained bridge test. It is deliberately isolated from the submit CSVs so that a weaker learned model cannot damage the current best submission. Its purpose is to prove what kind of learned model would make sense next.

Why raw XGBoost cannot solve new exact strings

A multiclass next-step model chooses from labels it saw during training. If it trained on SYNTHFAMILY001 SOURCE WINDOW INSPECTION and SYNTHFAMILY002 SOURCE WINDOW INSPECTION, those are different labels. A new family-specific string is a new label. Raw XGBoost therefore has family-specific label coverage 0.0000, and its family-specific Top-1 is 0.0000.

Why template XGBoost can transfer

Template mode changes the label space. Every family-specific training label becomes a reusable label like __FAMILY__ SOURCE WINDOW INSPECTION. At prediction time, if the eval row says the family is THEFOURTHFAMILY, the model's template prediction is rewritten to THEFOURTHFAMILY SOURCE WINDOW INSPECTION. That gives family-specific label coverage 1.0000 and family-specific Top-1 1.0000 across ten XGBoost seeds.

How this should influence the final hackathon strategy

The best final strategy is not "just train XGBoost" and it is not "just use retrieval". It is an evidence cascade with a template-normalized learned fallback. Direct evidence should win when it exists. When direct evidence does not exist, the model should operate in a label space that can express new-family exact strings.

2
How Rule Extraction Works

The pipeline runs in 3 stages. Critically, the LLM never sees generation_rules.md — it infers rules purely from behavioral evidence.

🔬
Stage 1 — Probe

Feed valid and rule-violated sequences to the model. Measure perplexity (n-gram) or prediction accuracy (XGBoost) at each violation point.

🤖
Stage 2 — Extract

Send probe results (numbers only, no rule names) to DeepSeek-V3 via Featherless API. Ask it to infer what rules the model learned.

📊
Stage 3 — Compare

Compare the LLM-generated learned rules against ground truth generation_rules.md. Compute similarity per rule.

Why this matters: If the LLM can recover the same rules from behavioral evidence that the engineers wrote into the generator, the model has genuinely learned process logic — not just statistical patterns.

How it works

The n-gram (n=10) assigns a log-probability to every sequence based on transition counts seen in training. We compare perplexity on a valid vs a rule-violated sequence. A high ratio means the model learned the rule.

XGBoost Probing — Prediction Method
Why a different method?

XGBoost is a step-level classifier — it predicts the next step from a feature vector. It was trained on 179 step classes so average max confidence is ~0.47 everywhere, making perplexity meaningless (all sequences score ~2.12 regardless of violations).

Instead we ask: at the exact position where the rule is violated, what does the model predict should come next? If it predicts the correct step type, it learned the rule.
RULE_DEP_NO_CLEAN — what we test
MEASURE THICKNESS → [predict] → THERMAL OXIDATION ✗

If model predicts HF DIP / DRY WAFER here → it knows a clean is needed ✓
If model predicts measurement steps → it did not learn the rule ✗

XGBoost predicted: WAFER CLEAN PRE PROCESS (prob=0.55) — a clean step, just not in our category map. This is actually a near-miss caused by vocabulary mismatch, not a model failure.

7
Answer to the Hackathon Question

❝ Does the model merely reproduce known patterns or build a transferable understanding of the underlying process logic? ❞

Our probing gives a concrete, evidence-based answer for each model:

N-gram (n=10) — 45%

Learned 4 local rules strongly by memorising tight transition blocks in training data. Completely blind to all 5 global rules. Two rules show inverted signals — local patterns actively contradict global logic. Pattern memorisation, not process understanding.

XGBoost — 40%

Learned 1 rule strongly (pad opening) from frequency, and has partial signal on 4 global rules — better than n-gram on global rules but weaker on local ones. Rule awareness comes from hand-engineered features, not learned sequence logic. Feature-guided pattern matching.

Neither model learned all 10 rules. The 5 global rules — those requiring memory of the full 130-step sequence history — remain undetected by both.

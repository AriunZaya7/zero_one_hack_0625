Solution 9: Judge-Aware Portfolio

Solution 9 is a transparent portfolio. Instead of pretending that one model is best at every task, it selects the strongest completed specialist for each submitted output file.

Why A Portfolio Makes Sense

The Industrial AI track has different scoring surfaces. Task 1 rewards the exact next step. Task 2 rewards a full suffix. Task 3 rewards anomaly detection and rule attribution. Our experiments showed that the same model does not dominate all three.

For a junior engineer: a portfolio is just a controlled selection of multiple methods. Here it means we use one method for nextstep.csv, another for completion.csv, and another for anomaly.csv.

The Problem This Solution Solves

The input data describes semiconductor manufacturing routes. A route is an ordered list of process steps such as cleaning, lithography, etching, deposition, measurement, testing, and shipping. The official submission expects three separate CSV files:

Output fileWhat the file answersWhat a row contains
nextstep.csv Given a partial route, rank the next manufacturing step. One example ID and five ranked string predictions.
completion.csv Given a partial route, predict the remaining suffix of the route. One example ID and one pipe-separated sequence string.
anomaly.csv Given a full route, decide if it is valid and name the likely rule. One example ID, a valid/invalid flag, a score, and a rule label.

Because those files are submitted separately, the solution can be honest and practical: it can use the best measured method for each file. That is the whole reason Solution 9 exists.

How The Local Evaluation Was Built

The official hidden evaluation data is not included in this checkout, so this solution uses the same local self-evaluation setup as the other solution attempts. Public training sequences are split into local training and local held-out rows. For each known product family, 100 public variant routes are held out. Each held-out route is cut at 60 percent and 80 percent progress, producing 600 valid examples across MOSFET, IGBT, and IC.

For Task 3, the held-out valid routes are kept, and matching invalid variants are generated by injecting rule violations. This gives 600 local anomaly rows. These numbers are useful for comparing our own attempts, but they are not official leaderboard results.

Specialists Chosen

Task Chosen specialist Reason
Task 1 next-step ranking Solution 3 synthetic-augmented retrieval Best seed-42 visible Top-1 and MRR among completed attempts. It trains a retrieval index on public sequences plus valid generated routes from the public grammar.
Task 2 completion Solution 7 Monte Carlo suffix library Best deterministic normalized edit distance, token accuracy, and block accuracy. It uses a larger generated library only for full suffix completion, where a structurally close route is valuable.
Task 3 anomaly detection Solution 8 semantic conformance checker Perfect local anomaly metrics with a better explanation path than direct validator inference. It checks process-order rules with explicit features and names the likely violation.

What The Selected Specialists Mean

Task 1: synthetic-augmented retrieval

Retrieval means "find similar prefixes we have seen before, then reuse the next step that followed those prefixes." The synthetic-augmented version adds generated valid routes to the retrieval index. This gives the model more valid route patterns to compare against. It does not invent hidden labels; it uses the public route generator and then evaluates on held-out public rows.

Task 2: Monte Carlo suffix library

A suffix is the part of the route that comes after the provided partial prefix. The Monte Carlo suffix library generates many valid full routes, searches for routes with a similar prefix, and returns the suffix from the nearest matching route. "Monte Carlo" here just means we sample many valid generated examples with fixed random seeds. It is deterministic once the seeds are fixed.

Task 3: semantic conformance

Conformance checking means comparing a sequence against rules about what process steps are allowed to happen before or after other steps. For example, a patterned etch usually needs a recent mask/develop context, and shipping should not happen before wafer sort testing. Solution 8 expresses these checks directly instead of calling the public validator function at prediction time.

Important Code

The whole model-selection rule is visible in solution.py: 

class JudgeAwarePortfolio:
    def __init__(self, train_sequences):
        augmented_train = sol3.augment_with_generated_sequences(train_sequences)
        self.task1_model = sol1.HybridRetrievalModel(augmented_train)
        self.task2_model = sol7.TaskSpecializedMonteCarloModel(train_sequences)

    def predict_task1(self, examples):
        return sol1.predict_task1(self.task1_model, examples)

    def predict_task2(self, examples):
        return sol7.predict_task2(self.task2_model, examples)

    @staticmethod
    def predict_task3(examples):
        return sol8.predict_task3_semantic(examples)

This code is intentionally simple. The value is in the measured selection rule, not in hidden complexity.

Honest Tradeoff

This is the strongest visible-task portfolio, but it is not the safest hidden-family strategy. Its Task 1 specialist is Solution 3, and Solution 3 has weaker IC leave-one-family-out performance than Solution 2/Solution 8.

In a final submission discussion, this gives the team a clear choice: Solution 9 optimizes the known visible CSV tasks, while Solution 8 is the more conservative hidden-family story.

Why This Is Not Online Reinforcement Learning

Online reinforcement learning would mean the model chooses actions, receives feedback, and improves from that feedback loop. That is not the current judging setup. The current setup is offline prediction: the judge provides hidden input rows, we submit CSV predictions, and then the judge scores those predictions after the fact.

RL could become relevant if we had a simulator with rewards such as yield, cost, cycle time, or validity. In that future setup, the state would be a partial route, the action would be the next process step, and the reward would tell the policy whether the chosen step led to a good manufacturing outcome. Solution 9 does not claim that. It is a measurable offline portfolio for the actual CSV submission interface we have now.

1 · The two philosophies

morgan Trained ML pipeline

  • XGBoost (best) and CatBoost gradient boosting on context-window step features
  • n-gram baselines (n = 2, 3, 4)
  • Separate Qwen-0.5B transformer fine-tune with its own OOD test split
  • One model serves all 3 tasks; beam search for completion; anomaly scoring + rule checker for Task 3
  • WandB logs, checkpoints, loss curves, hybrid-vs-legacy completion sweep

dev/bati Evidence-first cascade ("Solution 18")

  • 4-layer fallback: exact route memory → __FAMILY__ template normalization → generated-route retrieval → canonical op IDs
  • 18 solution attempts evaluated
  • Retrieval / memory heavy, lighter on learned weights
  • Framed for judges as an information-availability taxonomy
  • 110-family synthetic scaling probe (2 → 100 train families)

3 · Where they agree

Shared conclusions

  • You cannot output exact step strings never seen in training. Both hit 0.0 on novel-family exact strings — this is the central shared finding.
  • In-distribution next-step accuracy plateaus around ~0.74 regardless of method.
  • OOD degrades substantially without family-specific evidence.

4 · Where dev/bati goes further (the real gap)

What to borrow

  • Template normalization is their key OOD lever — morgan doesn't have it. Replacing the family prefix with a __FAMILY__ token recovers holdout-family next-step from 0.0 → 1.0 in the scaling probe (overall Top-1 0.62 → 0.77). morgan's boosting features don't exploit this, which is exactly why its OOD Top-1 stalls at 0.56–0.70 and completion exact stays 0. Highest-leverage fix.
  • Bigger scaling evidence: the 110-family sweep proves "more training families help only when a template transfers to the visible new family name." morgan has just 3 real families + leave-one-out, so it can't make the scaling argument.
  • Judge-ready narrative: exact route visible → perfect; related routes visible → ~0.76; fully unseen → hard limit.

5 · Where morgan is stronger / more honest

morgan's edge

  • Genuinely trained models (XGBoost + CatBoost + Qwen fine-tune, WandB logs, checkpoints, loss curves). The Infineon rubric explicitly wants "training artifacts: checkpoints, logs, loss curves" and penalizes "basic LLM wrappers." dev/bati's Solution 18 is largely retrieval + template grammar — lighter on learned modeling.
  • More conservative, honest headline numbers. dev/bati's "1.0000" results are conditioned on exact validator-valid routes being visible in the eval input — i.e. string-matching, not generalization. morgan's own solutions_comparison.md already makes this critique ("Public-overlap diagnostic: exact Top-1 1.0000 if held-out rows are allowed in the lookup"). dev/bati discloses it as a caveat but leads with the perfect score.
  • Cleaner reproducible eval harness: per-task / per-family JSON, hybrid-vs-legacy completion sweep, Task 3 rule-attribution accuracy 1.0 via an actual rule checker (f1 0.82 in-distribution).

Bottom line

Both branches reach the same core conclusion — exact unseen strings are unrecoverable and in-distribution tops out ~0.74 — but via opposite philosophies: morgan trains models, dev/bati builds an evidence cascade. dev/bati's decisive edge is family-template normalization plus a 110-family scaling probe that turns the exact-string ceiling from a wall into a solvable-for-derivable-strings problem. morgan's edge is a real trained-model pipeline with more honest headline numbers.

Highest-leverage move: add __FAMILY__ template normalization to the XGBoost / transformer pipeline and re-run leave-one-family-out — that's the lever that took dev/bati from 0.0 to 1.0 on held-out-family strings.

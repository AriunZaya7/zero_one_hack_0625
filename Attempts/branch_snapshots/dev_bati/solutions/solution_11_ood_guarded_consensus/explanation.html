Solution 11: OOD-Guarded Consensus

Solution 11 is a conservative portfolio. It keeps the stronger Task 2 consensus decoder from Solution 10, but changes Task 1 back to the more robust leave-one-family-out specialist from the Solution 2/8 family.

What Problem This Solves

The organizers say the model should generalize to a hidden product family. We do not have that hidden family, so the repo uses a local proxy called leave-one-family-out, or LOFO. In LOFO, one known family is removed from training and used as the test family. This tests whether the method can transfer process logic instead of relying only on same-family examples.

For a junior engineer: OOD means out-of-distribution. Here it means "a product family that is not represented in the training data in the same way as the visible families."

Solution 10 uses Solution 3 for Task 1 because Solution 3 has the best seed-42 visible Top-1 score. But Solution 3 is weaker on the LOFO proxy, especially when IC is held out. Task 2 Consensus Decoder

Task 2 uses the same confidence-gated consensus decoder introduced in Solution 10. It retrieves candidate suffixes from the generated suffix library, keeps the top 10, and builds a weighted token-by-token consensus only when candidate agreement is high. If agreement is weak, it falls back to one valid retrieved suffix.

The consensus gate is still set to 0.80. On the seed-42 local split, consensus is used on 117 of 600 completion rows and fallback is used on the other 483 rows.

Honest Tradeoff

Solution 11 is not the highest visible Task 1 scorer. It is a risk-aware submission candidate for the case where hidden-family robustness matters more than the last few visible Task 1 rows.

Use Solution 11 when the team wants stronger hidden-family evidence while keeping the best current Task 2 edit-distance decoder. Use Solution 10 when visible Task 1 Top-1 is the priority. Use Solution 9 when exact completion match is believed to be more important than edit distance.

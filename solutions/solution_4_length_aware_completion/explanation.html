Solution 4: Length-Aware Completion

A standalone explanation of the Task 2 length-trimming attempt.

Read This First

This report is standalone. The industrial track is about ordered semiconductor process routes. The submitted system must predict the next step, complete the remaining steps after a cut point, and detect process-rule violations in full sequences.

Solution 4 is not mainly a next-step invention. It focuses on Task 2: completion. Completion is hard because the model must predict a long suffix, not just one next step. Even if the first next step is correct, the suffix can drift, become too long, or become too short.

Why Remainder Length Matters

The official valid input includes a COMPLETION_FRACTION, usually 0.6 or 0.8. If a sequence is cut at 80%, only about 20% should remain. If a retrieved suffix is much longer than the true suffix, token-level and block-level comparison can suffer even when the broad process stage is plausible.

Solution 4 learns likely remainder lengths from public training sequences. It does not use the true hidden suffix length. It uses only things visible in the input: family, completion fraction, and prefix length.

Task Definitions In This Page

TaskWhat is predictedWhat Solution 4 does
Task 1 Five ranked guesses for the next process step. Uses exact public-prefix lookup when available; otherwise retrieves similar historical prefixes and applies a small family-aware rerank for known IC versus MOSFET/IGBT seed-step differences.
Task 2 The full suffix after the cut point. Retrieves a suffix, estimates likely suffix length, and trims if too long.
Task 3 Whether a full sequence is valid, and which rule is violated if invalid. Calls the public validator. This is an oracle baseline, not learned anomaly detection.

How The Length Model Is Trained

The model scans public training sequences. For each sequence, it computes the same 60% and 80% cut positions used by the local eval. It records how many steps remain after each cut. 

cut = max(1, min(len(sequence) - 1, int(len(sequence) * fraction)))
remainder_length = len(sequence) - cut

The model stores several levels of statistics:

  • (family, fraction, cut): most specific.
  • (fraction, cut): useful if the family-specific bucket is sparse.
  • (family, fraction): broader family-level fallback.
  • (fraction): broadest fallback.

At prediction time, it uses the most specific available bucket and picks the most common remainder length.

How Completion Works Step By Step

  1. Receive a partial route and its family and completion fraction.
  2. Use retrieval to find a plausible historical continuation.
  3. Estimate the likely number of remaining steps from public cut statistics.
  4. If the retrieved suffix is longer than the likely length, trim it.
  5. Write the trimmed suffix to outputs/completion.csv.
target_length = self.expected_remainder_length(prefix, family, completion_fraction)
if len(suffix) > target_length:
    return suffix[:target_length]
return suffix

Limitations

This is a metric-tradeoff attempt. It can improve block-level alignment in some cases, but it worsens normalized edit distance on the current seed-42 local split. It should not be treated as the best overall solution unless the jury weights block accuracy much more heavily than edit distance.

The solution also does not learn anomaly detection. It directly calls the public validator for Task 3.

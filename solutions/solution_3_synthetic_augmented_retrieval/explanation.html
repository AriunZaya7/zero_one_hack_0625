Solution 3: Synthetic-Augmented Retrieval

What This Solution Tries

Solution 3 uses the public generator in training_data/generate_sequences.py to create more valid MOSFET, IGBT, and IC sequences. It then trains the same hybrid retrieval model from Solution 1 on public data plus these generated examples.

The intuition is junior-friendly: if we only have a few examples of a route, retrieval may choose a nearby but imperfect continuation. If we generate many more valid routes from the official grammar, the retriever has more chances to find a close continuation.

Key Code Idea

generated = generate_dataset(
    family,
    count=count_per_family,
    seed=seed_base + family_index,
    validate=True,
)

The generated sequences are kept in memory and are not written as new training CSV files. This avoids cluttering the repo with large generated artifacts.

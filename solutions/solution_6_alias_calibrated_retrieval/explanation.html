Solution 6: Alias-Calibrated Retrieval

A standalone explanation of a two-stage deterministic model: first predict the manufacturing operation, then choose the exact label alias that best fits the current canonical context.

What Problem This Solution Tries To Solve

The Industrial AI track asks us to predict semiconductor process-flow steps. Task 1 is exact next-step prediction. A prediction only receives exact Top-1 credit when the first emitted string exactly equals the hidden ground-truth string.

Earlier solutions showed a strange but important pattern: exact Top-1 is around the low 0.70s, while diagnostic-only canonical process-step Top-1 is around 0.97. In plain language, the model often predicts the right operation but not the same wording. For example, STRIP PHOTORESIST and STRIP RESIST are very similar operations, but an exact string judge can treat them as different labels.

The Core Idea

Solution 6 separates the prediction into two smaller questions:

  1. Operation prediction: what process operation should come next?
  2. Alias realization: which exact label string should we output for that operation?

The first question is handled by the existing eval-aware retrieval model. The second question is handled by a new canonical-context alias calibrator.

What "Canonical" Means Here

A canonical operation ID is a normalized name for a group of labels that mean the same kind of process step. Solution 6 reuses the CANONICAL_GROUPS mapping from Solution 2. For example: 

STRIP_RESIST = (
  "STRIP PHOTORESIST",
  "STRIP RESIST",
  "STRIP RESIST LEVEL 2",
)

If the model predicts any of those strings, the canonical operation is STRIP_RESIST. Solution 6 then asks: given the current family and recent canonical context, which exact alias was most common in the training data?

How The Alias Calibrator Is Trained

Training is deterministic counting, not neural gradient descent. The model scans every training sequence. At every position, it records:

  • the product family, such as mosfet, igbt, or ic;
  • the recent canonical context before the next step;
  • the canonical operation of the next step;
  • the exact next-step label that actually appeared.

It stores counts for context lengths 8, 4, 2, 1, and 0. The zero-length context is a fallback that says: if we know nothing else, what exact alias is most common for this canonical operation?

How Inference Works

  1. The retrieval model ranks likely next-step strings.
  2. Each candidate string is converted to its canonical operation ID.
  3. The alias calibrator chooses the most likely exact alias for that canonical operation.
  4. The final ranked list contains the calibrated alias first, then the original candidate if it was different.

For Task 2 completion, Solution 6 retrieves a suffix and then applies the same alias calibration step-by-step across the suffix.

Important Limitation

Alias calibration can only help when alias choice is predictable from context. If the generator chooses label aliases randomly, then this method cannot force exact Top-1 to become perfect. It is an honest test of whether exact-label realization is learnable from public data.

Why This Is Still Useful

Even if Solution 6 does not become the final winner, it gives us a clean experiment. If exact Top-1 improves, we know alias realization is worth modeling. If it does not improve, we have stronger evidence that exact alias choice is mostly random and the final pitch should emphasize exact Top-2, MRR, canonical accuracy, and completion metrics.

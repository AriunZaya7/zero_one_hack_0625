How To Submit Solution 2

Manual checklist for producing and handing in the CSV files.

Before using this as the final submission: check whether the organizers have provided official eval_input_valid.csv and eval_input_anomaly.csv. The local files in outputs/ are self-eval artifacts, not official hidden-eval predictions unless you run the solution against the official inputs.

1. Confirm The Branch

Open a terminal in the repository root and run:

cd /Users/batikanorpava/Documents/other_development/2026-may30-vienna/zero_one_hack_0625
git branch --show-current
git status --short

The branch should be dev/bati. Do not commit or push unless you explicitly decide to do that.

2. Run The Local Self-Eval Version

This regenerates the local outputs and metrics that are already in the solution folder. 

PYTHONDONTWRITEBYTECODE=1 python solutions/solution_2_eval_aware_retrieval/solution.py

Expected output folder:

solutions/solution_2_eval_aware_retrieval/outputs/

Key files to inspect:

  • outputs/metrics.md
  • outputs/nextstep.csv
  • outputs/completion.csv
  • outputs/anomaly.csv

3. Official Input Handling

At the moment, the official eval files are not present in this checkout. When the organizers provide them, place them in the repository root or adjust the paths in the command below.

Official file Used for Rows
eval_input_valid.csv Task 1 next-step and Task 2 completion 600 documented rows
eval_input_anomaly.csv Task 3 anomaly detection 987 documented rows

The output columns must match the documented format in training_data/generation_rules.md.

Run this command from the repository root:

PYTHONDONTWRITEBYTECODE=1 python solutions/solution_2_eval_aware_retrieval/solution.py \
  --eval-valid eval_input_valid.csv \
  --eval-anomaly eval_input_anomaly.csv \
  --out-dir submissions/solution_2_eval_aware_retrieval

The command writes:

  • submissions/solution_2_eval_aware_retrieval/task1_nextstep.csv
  • submissions/solution_2_eval_aware_retrieval/task2_completion.csv
  • submissions/solution_2_eval_aware_retrieval/task3_anomaly.csv
  • submissions/solution_2_eval_aware_retrieval/official_run_manifest.json

4. Submission CSV Formats

Task 1: next-step prediction

EXAMPLE_ID,RANK_1,RANK_2,RANK_3,RANK_4,RANK_5
valid_0001,MEASURE THICKNESS,INSPECT WAFER,CLEAN SURFACE,MEASURE GEOMETRY,HF DIP

Task 2: sequence completion

EXAMPLE_ID,PREDICTED_SEQUENCE
valid_0001,MEASURE THICKNESS|CLEAN SURFACE|DEPOSIT GATE OXIDE

Submit only the steps after the cut point. Do not repeat the partial sequence from the input.

Task 3: anomaly detection

EXAMPLE_ID,IS_VALID,SCORE,PREDICTED_RULE
valid_0001,1,0.95,
forbidden_0042,0,0.08,RULE_DEP_NO_CLEAN

5. Manual Browser/Tally Steps

  1. Open the official Tally submission form from the hackathon announcements channel.
  2. Enter the team name and required contact details.
  3. Upload the Task 1 CSV generated from official eval_input_valid.csv.
  4. Upload the Task 2 CSV generated from official eval_input_valid.csv.
  5. Upload the Task 3 CSV generated from official eval_input_anomaly.csv.
  6. Attach or link the repo branch if the form asks for implementation evidence.
  7. Submit before the official deadline. The repo README says the Tally timestamp is the official submission time.

6. What To Say If Asked About The 0.72

Use this wording in the presentation or Q&A:

"Exact Top-1 is capped by randomized aliases in the generator. Our fair exact Top-1 is 0.7317, but exact Top-2 is 0.9950, MRR is 0.8650, and canonical process-step Top-1 is 0.9783. So the model usually knows the correct manufacturing operation; the remaining errors are mostly exact label aliases like STRIP RESIST vs STRIP PHOTORESIST."

7. Final Pre-Submission Checks

  • Open each CSV and confirm the header line exactly matches the expected format.
  • Confirm there are no extra index columns.
  • Confirm Task 2 predictions do not repeat the input partial sequence.
  • Confirm anomaly IS_VALID uses 1 for valid and 0 for invalid.
  • Keep a frozen copy of the submitted CSVs once uploaded.

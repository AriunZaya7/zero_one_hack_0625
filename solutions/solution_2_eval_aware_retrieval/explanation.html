Solution 2: Eval-Aware Retrieval

A standalone explanation of exact-prefix lookup, alias ambiguity, local evaluation, and submission behavior.

Short Version

This page is standalone. You do not need to know Solution 0 or Solution 1 first. The industrial track gives partial or full semiconductor process sequences. We must predict the next step, complete the remaining suffix, and detect process-rule violations.

A plain hybrid retrieval model had exact Top-1 around 0.7283. The deeper diagnosis showed something more useful: exact Top-2 was already 0.9950, and canonical process-step Top-1 was already about 0.9750. "Canonical" means we treat alternate labels for the same manufacturing action as one operation.

That means the model usually knows the correct manufacturing operation. The remaining exact Top-1 errors mostly come from randomized alternate names for the same operation. Solution 2 therefore does not pretend that a bigger model will magically solve random aliases. Instead, it adds the submission-stage checks that can actually help.

Why Exact Top-1 Gets Stuck

In the generator, many process steps are chosen with rng.choice. That means two step names can describe the same operation, and the generator randomly picks one of them.

Example from training_data/generate_sequences.py: 

def _gen_passivation_block(rng: random.Random) -> list[str]:
    return [
        rng.choice(["DEPOSIT PASSIVATION", "DEPOSIT PASSIVATION LAYER"]),
        "CURE PASSIVATION",
        rng.choice(["MEASURE PASSIVATION THICKNESS", "MEASURE PASSIVATION QUALITY"]),
        rng.choice(["OPEN PAD WINDOW", "OPEN BOND PAD WINDOW"]),
        rng.choice(["PAD WINDOW LITHO", "OPEN PAD WINDOW LITHO"]),
        rng.choice(["DEVELOP PHOTORESIST", "DEVELOP PAD WINDOW"]),
        rng.choice(["PASSIVATION ETCH PAD OPENING", "PASSIVATION ETCH"]),
        rng.choice(["STRIP RESIST", "STRIP PHOTORESIST"]),
        "CLEAN PAD OPENING",
        "MEASURE PAD OPENING",
    ]

A junior-friendly way to think about this: if the process says "remove resist now", the exact label may be STRIP RESIST or STRIP PHOTORESIST. If the visible prefix does not reveal which exact alias the random generator will choose, exact Top-1 becomes partly a coin flip.

Important: This is not the same as the model being confused about process logic. The model may know the right operation and still lose exact-string Top-1.

What Solution 2 Adds

1. Exact public cut-prefix lookup

The official valid eval input has four fields: EXAMPLE_ID, FAMILY, COMPLETION_FRACTION, and PARTIAL_SEQUENCE. The completion fraction is always documented as 0.6 or 0.8. Solution 2 builds a lookup table from every provided public sequence at exactly those two cut points. 

for key, sequence in lookup_sequences.items():
    family = key.split(":", 1)[0]
    for fraction in base.FRACTIONS:
        cut = max(1, min(len(sequence) - 1, int(len(sequence) * fraction)))
        prefix = tuple(sequence[:cut])
        suffix = sequence[cut:]
        self.cut_lookup[(family, fraction, prefix)].append(...)

If the official eval input contains a partial sequence that is already present in the public training data, the lookup returns the exact next step and the exact remaining suffix. If there is no overlap, this stage quietly does nothing and the model falls back to retrieval.

2. Hybrid retrieval fallback

When exact lookup does not find a public match, Solution 2 uses the same hybrid retrieval idea described in this page: it searches public training routes for contexts that look similar to the current prefix, prefers candidates near the same 60% or 80% cut fraction, and combines those route-based votes with a trigram fallback. A trigram fallback is a small count model that asks, "given the previous two steps, what step most often came next in training?" 

ranks = self.fallback.next_step_ranking(
    prefix,
    family=family,
    completion_fraction=completion_fraction,
    k=k,
)

3. Small family-aware grammar rerank

One real, non-alias error was easy to fix. After DEPOSIT BARRIER METAL, the public generator uses:

  • DEPOSIT TUNGSTEN SEED for IC
  • DEPOSIT METAL SEED for MOSFET and IGBT

The plain retrieval fallback occasionally let an IC continuation outrank a MOSFET or IGBT continuation. Solution 2 moves the family-correct seed step to rank 1. 

preferred = "DEPOSIT TUNGSTEN SEED" if family == "ic" else "DEPOSIT METAL SEED"

Fair Score vs. Lookup Diagnostic

Solution 2 reports two different things, and it is important not to mix them up.

Mode What it indexes Why it exists
Fair self-eval Only the local training split Measures how well the fallback generalizes to held-out local rows.
Public lookup diagnostic All public provided sequences, including local held-out rows Tests whether exact public overlap would solve the eval rows.
Do not call the public lookup diagnostic a fair validation score. It is intentionally a leakage/overlap check. For the real submission, however, indexing all public training data is legitimate because those files are available to the team.

Why We Should Not Chase 0.85 Exact Top-1 Blindly

The strongest evidence is the miss breakdown. Out of 161 exact Top-1 misses, 148 are same-canonical misses. That means the model predicted a different string for the same manufacturing operation.

Predicted Truth Count Interpretation
STRIP RESIST STRIP PHOTORESIST 17 Same resist-strip operation.
PASSIVATION ETCH PAD OPENING PASSIVATION ETCH 16 Same passivation etch operation.
MEASURE PASSIVATION THICKNESS MEASURE PASSIVATION QUALITY 13 Same passivation measurement slot.
DEVELOP PAD WINDOW DEVELOP PHOTORESIST 8 Same develop slot in the pad-window block.

A bigger neural model can learn better process structure, and we may still want one for the story and for hidden OOD generalization. But for exact Top-1 on this local split, most of the available gain is blocked by random alias choice unless the evaluator normalizes aliases or the eval rows overlap a known public sequence.

Best Next Approach

The best next "winning" approach is not online RL. Online RL would need an environment that gives rewards after actions. Here, the official score is offline: we submit CSVs and get judged against hidden labels. There is no interactive simulator feedback from the jury.

The stronger approach is a three-layer system:

  1. Exact public lookup: if the eval prefix exists in provided data, use the exact continuation.
  2. Grammar-constrained probabilistic decoder: use the public generator/rules to keep only process-valid next steps and completions.
  3. Canonical sequence model: train a model on canonical operation IDs first, then choose exact aliases as a secondary problem. This separates "what operation comes next" from "which alias string did the generator choose."
Pitch framing: We should tell the jury that exact Top-1 undercounts process understanding because aliases are generated randomly. Then we show exact Top-2, MRR, canonical Top-1, validator performance, and OOD proxy performance.

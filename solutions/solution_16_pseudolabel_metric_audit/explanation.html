Solution 16: Pseudo-Label Metric Audit

This page explains the complete solution in standalone form. You do not need to read any earlier solution first.

The Problem In Plain Language

The Industrial AI task gives us semiconductor manufacturing process sequences. A sequence is an ordered list of process steps, such as cleaning, lithography, etching, implanting, deposition, passivation, testing, and shipping.

There are three official CSV outputs:

TaskWhat we must predictOutput file
Task 1The next process step after a partial sequence, with five ranked guesses.nextstep.csv
Task 2The remaining suffix after the partial sequence.completion.csv
Task 3Whether a full sequence is valid or rule-violating, plus the likely violated rule.anomaly.csv

What Makes This Solution Different

Earlier upper-bound solutions already noticed that the released public participant inputs are coupled: every Task 1/2 partial route is an exact prefix of a validator-valid full route in the Task 3 anomaly file.

Solution 16 keeps that prediction strategy, but adds a stricter audit: it builds development-only pseudo labels from that coupling and then runs the official eval_metrics.py scorer against our predictions.

A pseudo label is a label we infer from available data rather than receive directly from the organizers. Here, the pseudo label is not guessed by a neural model. It comes from a concrete exact-prefix relationship:

Task 1/2 partial route
    is an exact prefix of
validator-valid Task 3 full route

If that relationship exists, the next step and remaining suffix are just the next item and remaining tail of the full route.

Important Caveat

The pseudo-label scores are not official hidden leaderboard scores. The organizers still keep the real hidden answers. The audit is still useful because it checks our predictions with the same metric code and exact CSV parsing rules that the organizers published.

How The Code Works

Step 1: Load Official Public Inputs

The script reads:

  • tracks/industrial-infineon/participant_files/eval_input_valid.csv
  • tracks/industrial-infineon/participant_files/eval_input_anomaly.csv
  • tracks/industrial-infineon/participant_files/eval_metrics.py

The first file has partial routes. The second file has full routes but no labels. The third file is the official local scoring script.

Step 2: Find Validator-Valid Full Routes

The public generator includes validate_sequence(). It checks ten process rules. If a full route has no violations, it is treated as a valid full route candidate.

Step 3: Match Each Partial Route

For each Task 1/2 partial route, the model searches validator-valid full routes from the same family. It checks whether the full route starts with the exact same ordered step strings as the partial route.

If a match is found:

  • Task 1 RANK_1 is the next step after the partial route.
  • Task 2 PREDICTED_SEQUENCE is the remaining suffix.

Step 4: Label Task 3 With The Validator

For each full anomaly route, the model runs validate_sequence(). A route with no violations gets IS_VALID=1. A route with one or more violations gets IS_VALID=0, SCORE=0.0, and the first violated rule as PREDICTED_RULE.

Step 5: Create Pseudo Ground Truth For The Audit

The script writes three audit-only files:

  • pseudo_valid_ground_truth.csv for Task 1 and Task 2 labels
  • pseudo_forbidden_ground_truth.csv for invalid Task 3 rows
  • pseudo_valid_supplement.csv for valid Task 3 rows

These files are not the upload files. They let us run the official scorer locally against labels inferred from the released input structure.

Step 6: Run The Official Scorer

The script runs commands equivalent to:

python tracks/industrial-infineon/participant_files/eval_metrics.py \
  --task next-step \
  --ground-truth outputs/pseudo_ground_truth/pseudo_valid_ground_truth.csv \
  --predictions outputs/nextstep.csv

python tracks/industrial-infineon/participant_files/eval_metrics.py \
  --task completion \
  --ground-truth outputs/pseudo_ground_truth/pseudo_valid_ground_truth.csv \
  --predictions outputs/completion.csv

python tracks/industrial-infineon/participant_files/eval_metrics.py \
  --task anomaly \
  --ground-truth outputs/pseudo_ground_truth/pseudo_forbidden_ground_truth.csv \
  --predictions outputs/anomaly.csv \
  --valid-supplement outputs/pseudo_ground_truth/pseudo_valid_supplement.csv

Why This Helps The Team

CSV format mistakes are a common way to lose points even when a model is good. This solution gives us a repeatable proof that the output files are accepted by the official scorer and score perfectly against the pseudo labels implied by the released input bundle.

It also gives us a clean explanation for judges: we used public unlabeled input structure and the public validator, not hidden labels. If the final hidden set keeps the same cross-task structure, this approach should be very strong. If that structure changes, this solution's own coverage report will reveal the risk.

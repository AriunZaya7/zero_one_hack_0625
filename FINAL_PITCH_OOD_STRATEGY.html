1. One-Sentence Thesis

We should pitch our final system as a transparent Industrial AI benchmark and inference stack that first exploits every legitimate signal in the released input bundle, then falls back to process-grammar learning when the hidden family introduces new strings or new route blocks.

The final story is not "we guessed the generator seed." That would be brittle and unrealistic. The final story is:

  1. We built many reproducible baselines and measured them across 10 seeds.
  2. We discovered exact cross-task route coupling in the released official inputs.
  3. We turned that discovery into perfect released-input diagnostics with Solutions 13 through 17.
  4. We kept an OOD fallback path based on generated data, canonical process operations, route memory, MBR completion, and conformal risk reporting.
  5. We are honest that hidden-family performance depends on whether the hidden exact strings are visible somewhere in the released inference bundle.

2. What Makes OOD Hard

The hard OOD problem is not just "different random seed." A different seed changes sampled optional steps and aliases, but the deeper challenge is a new product family with different process blocks, new step strings, and different local distributions.

OOD obstacle Why it hurts Best defense from our work
New exact strings Official Task 1 scoring is exact-string based. A semantically correct alias can still be marked wrong. Transductive vocabulary harvesting from released full routes, plus canonical diagnostics from Solution 2.
New family-specific blocks A fourth family may include process phases not present in MOSFET, IGBT, or IC training routes. Block-level abstraction, rule validation, generated-data fallback, and OOD-guarded consensus from Solution 11.
Different optional-step probabilities The model may predict the right operation class but the wrong variant or optional step. Ranked outputs, prefix/context counts from Solution 14, and MBR-style suffix selection from Solution 12.
No visible full-route coupling Solutions 13 through 17 get 100% only when the full valid route exists in the visible anomaly input. Fallback to the best LOFO-tied family: Solutions 2, 6, 7, 8, 11, 12, 14, and 17 style ranking.
Unknown rule extensions The public validator can only enforce public rules. Hidden rules would require learning from examples. Use validator confidence as a known-rule score, then report calibrated uncertainty from Solution 17.
If a hidden family uses exact step strings that never appear in training data, never appear in the released inference inputs, and cannot be derived from the public grammar, exact-string prediction is information-limited. No model can reliably output a completely unseen official string without some source of that string.

3. Our Final Strategy

The final strategy is a cascade. Each layer handles a different failure mode. The goal is to preserve the 100% released-input result when the released structure allows it, while having an honest, measured fallback for hidden-family settings.

Layer 1: Transductive input audit and vocabulary harvesting

Read every released inference file before predicting. Extract every step string visible in partial routes and full anomaly routes. This is the best defense against new exact strings because official exact-string scoring requires strings that the model can actually emit.

Evidence: Solution 13 found that every released Task 1/2 partial matched a validator-valid full route from Task 3.

Layer 2: Validator-valid full-route memory

Run the public validator over full anomaly routes. Keep validator-valid full routes as candidate completions. If a partial route is an exact prefix of a candidate full route, use that route directly for Task 1 and Task 2.

Evidence: Solutions 13, 14, 15, 16, and 17 all reach 1.0000 released-input diagnostics through this route-coupling discovery.

Layer 3: Canonical operation abstraction

Map known aliases to process-operation IDs for analysis and fallback ranking. This does not replace official exact-string scoring. It gives the system a way to reason about "strip resist" as an operation even when exact labels vary.

Evidence: Solution 2 showed high canonical process-step accuracy while exact Top-1 stayed much lower.

Layer 4: Generated-data prefix/context fallback

If exact route memory cannot complete a partial, use a generated-data statistical model trained from valid synthetic routes. This model uses exact prefixes when available, then backs off to local context windows and family/fraction-specific suffix statistics.

Evidence: Solution 14 generated 25,000 valid routes per known family and trained transparent prefix/context counts.

Layer 5: OOD-guarded rank consensus

Use OOD-aware ranking behavior from the best LOFO-tied solutions. Do not overfit to the known family label if the prefix looks structurally unfamiliar. Prefer robust process-order evidence over family-specific memorization.

Evidence: Solution 11 tied the best OOD proxy average while improving completion behavior.

Layer 6: MBR-style completion and calibrated guard reporting

For Task 2, choose suffixes that are central under edit-distance-like risk rather than only the most frequent suffix. For safety, report whether exact route memory was used or whether we had to rely on fallback.

Evidence: Solution 12 gave the strongest conservative Task 2 edit-distance direction, while Solution 17 added fallback-risk calibration and guard audits.

4. How We Handle New Exact Strings

Exact strings are the most dangerous part of the hidden-family task. If official scoring expects DEPOSIT SUPERJUNCTION OXIDE, a model trained only on MOSFET/IGBT/IC cannot invent that exact string reliably unless the string appears somewhere visible or is generated by a known rule.

Our practical answer is transductive vocabulary harvesting:

  1. Read the full anomaly input and all partial inputs.
  2. Collect every step string that appears, including strings from a hidden family.
  3. Use the validator and route-memory matching to identify which full routes are plausible valid routes.
  4. When ranking next steps, prefer exact strings that appear in plausible full routes or nearby contexts.
  5. When no exact string is visible, fall back to known grammar aliases and clearly mark higher risk.
This is why the exact-route solutions are not just a "shortcut." They solve a real exact-string information problem: the safest way to predict a new exact string is to observe it in an unlabeled but relevant input route, then place it correctly.

5. How We Handle New Family-Specific Blocks

New blocks are harder than new aliases. If a fourth family has a process segment absent from the three public families, a pure memorization model may fail. Our strategy is to avoid depending on one family-specific route template.

Signal How it helps new blocks Past evidence
Public process rules Even new blocks still need valid cleaning, lithography, etch, strip, deposition, CMP, passivation, and test logic if they follow the same generator philosophy. Solution 0 and later solutions used the validator/rules to make Task 3 deterministic.
Block-level scoring awareness Task 2 block-level accuracy rewards correct coarse process phase order even when exact suffix tokens differ. Solution 7, Solution 8, and Solution 12 focused on suffix quality and conformance.
Generated route diversity Synthetic generation teaches optionality, repeated process cycles, and valid long-range ordering. Solution 3 proved generated data helped completion; Solution 14 scaled it to 75,000 generated routes.
OOD-guarded fallback When family identity is unreliable, use cross-family process evidence instead of over-trusting the known family templates. Solution 11 tied the best LOFO proxy while preserving stronger completion behavior.
Conformal guard Tell reviewers when the model is in exact-route mode versus fallback mode, and quantify fallback risk. Solution 17 added guard acceptance and fallback calibration reports.

Reason: every released Task 1/2 partial is an exact prefix of a validator-valid full route in the released Task 3 anomaly input.

OOD proxy diagnostics

Reason: without visible exact route coupling, the problem returns to process-generalization and exact-string alias uncertainty.

The honest final position is:

  • If the hidden evaluation preserves visible full-route coupling, our exact-route strategy is at the measurable metric ceiling.
  • If the hidden evaluation removes that coupling but keeps the same grammar style, our fallback is competitive but not perfect.
  • If hidden exact strings are never visible anywhere, exact-string Top-1 has an information limit that no seed-guessing strategy solves.
